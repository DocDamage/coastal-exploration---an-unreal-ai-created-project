# Native setup and public-source boundary

The tested compatibility candidate is Unreal 5.7.4 (CL 51494982), Visual Studio 2022 17.14.38, MSVC 14.44.35228 (toolset directory 14.44.35207), Windows SDK 10.0.26100.0. The inspected vendor core assets also compile and run in this host; full vendor-demo compatibility is not claimed. UE 5.8 was not selected. Epic lists VS 2022 17.14 as recommended for UE 5.7: [official compiler setup](https://dev.epicgames.com/documentation/en-us/unreal-engine/setting-up-visual-studio-development-environment-for-cplusplus-projects-in-unreal-engine).

The local host is external to this repository at `../LocalHost/CoastalExploration`. Its descriptor is `CoastalExploration.uproject`; it retains Epic's unmodified `TP_ThirdPerson` module and `TP_ThirdPersonEditor` / `TP_ThirdPerson` target names. It was assembled from the installed engine's `Templates/TP_ThirdPerson` and the Characters, Input and LevelPrototyping shared packs. Each shared pack's Content belongs under its own mount name, not at the Content root. The initial wrong mount layout caused missing input/character references; this was corrected before native test execution.

The C++ template includes inactive variant code from Epic. The host uses the standard Third Person map/GameMode; no combat variant was selected. Template source and binaries remain external to public source. The host's `Plugins/CoastalFoundation` and `Plugins/CoastalVendorIntegration` are directory junctions to this repository's original plugins, so each has one maintained source. Do not replace the junction with an outdated copy.

The display-enabled candidate additionally selects `GameEngine=/Script/CoastalVendorIntegration.CoastalHostGameEngine` under `[/Script/Engine.Engine]`, retaining the standard `UGameUserSettings` and CommonUI viewport. This original host extension replaces its inherited UE 5.7 resize delegate with runtime bookkeeping only. The stock callback also calls SetScreenResolution/ConfirmVideoMode, which conflicts with Coastal's unsaved trials. The extension does not apply or save preferences, remove other objects' delegates, or relax Coastal's native viewport/foreground/confirmation guards. Re-audit this engine-specific binding on an engine upgrade. Disable Alt-Enter/F11 fullscreen shortcuts in the host input settings so they cannot compete with the display owner.

Under `[SystemSettings]`, set `CommonUI.ShouldVirtualAcceptSimulateMouseButton=0`. The CommonUI dependency is retained for AGIS, but Coastal's native panel owns gamepad confirmation. The default CommonUI analog cursor intercepts confirm and converts it into a mouse click; actual Slate-event testing reproduced a focused Start button that did not activate. Disabling that conversion lets the existing native key handler execute. No vendor inventory UI or CommonUI action-menu stack is used by this host. The `gamepad_ui` development probe navigates with D-pad and confirms through Slate, captures focused states, and performs the integrated campaign sequence. Add `-CoastalText150` to select 150% native text through the options UI; otherwise it applies defaults for the session. World positioning and interactions retain the deterministic test driver, so this is UI event-routing evidence, not physical controller-only traversal.

The current acceptance candidate binds Coastal look/sprint to the inspected template actions and loads three independent classes plus real local sounds from `/Game/Coastal/Audio`; include that directory in cooking. Licensed-derived ambience/action assets remain external. Foreground audio runs require sound enabled; use `-CoastalRecordAudio` only for disposable development evidence. `-CoastalAcceptance=audio` waits through the finite recording before checking the still-unacknowledged mission. `display` exercises actual window trials; `display_reload` requires the same test-slot expectation and no launch resolution/window overrides. These probes do not establish physical-device acceptance.

## Build and engine checks

Set `$Engine` to the inspected installation directory and `$Project` to the actual absolute host descriptor. Commands are PowerShell:

```powershell
& "$Engine/Engine/Build/BatchFiles/Build.bat" TP_ThirdPersonEditor Win64 Development "-Project=$Project" -WaitMutex -NoHotReloadFromIDE -Compiler=VisualStudio2022
& "$Engine/Engine/Build/BatchFiles/Build.bat" TP_ThirdPerson Win64 Development "-Project=$Project" -WaitMutex -NoHotReloadFromIDE -Compiler=VisualStudio2022
& "$Engine/Engine/Binaries/Win64/UnrealEditor-Cmd.exe" $Project -NullRHI -Unattended -NoSound '-ExecCmds=Automation RunTests Coastal.' '-TestExit=Automation Test Queue Empty' "-ReportExportPath=$Evidence/unreal-automation"
```

All 38 supplied tests plus the actual AGIS test pass under NullRHI; the AGIS test reports 24 vendor demo tag warnings. That mode is suitable for these unit-style engine tests, not room creation or visual verification. The full editor room recipe needs a real rendering backend; use `-ExecutePythonScript` with `-RenderOffscreen -d3d11` for unattended generation. PythonScriptPlugin and EditorScriptingUtilities are enabled only for Editor targets.

The current integrated map is `/Game/Coastal/Maps/L_SystemsTest_Integrated`; the earlier smoke map `L_SystemsTest_Native` is preserved. Its native room manifest passed. The failed NullRHI attempt's partial `L_SystemsTest` is preserved locally and excluded from the package map list. The recipe's map path changed deliberately to avoid overwriting that evidence; logical map ID, world IDs, items and mission contracts did not change.

The integrated room uses the original child BP_CoastalGameMode and BP_CoastalPlayerController, with the actual template character. Four authored safety volumes and the native room manifest pass. One controller host component attaches actual AGIS, Hyper and existing Coastal owners, then calls the single bootstrap. [Vendor contract and wrapper-generation source](M1_VENDOR_INTEGRATION.md).

## Dependencies, cooking and packaged acceptance

The user-supplied AGIS and Hyper packages are available and copied to the external host at exact INVENTORY and Hyper mounts. No purchased files are in the source repository. The specific mounts are ignored if introduced there later; original Coastal assets are not blanket-ignored. Do not copy vendor project settings wholesale. See the vendor contract for the CommonUI viewport key, tags and collision channel.

Set both startup maps and MapsToCook to L_SystemsTest_Integrated. Add cook directories `/Game/Coastal/Integration`, `/Game/INVENTORY/Core/InventoryComponents`, `/Game/INVENTORY/Core/Libraries` and `/Game/INVENTORY/Items`; these cover runtime-reflected loads and definitions. Dependencies of the real Hyper child are discovered by the cook. The current package is a development build and includes vendor dependencies reached through those assets.

```powershell
& "$Engine/Engine/Build/BatchFiles/RunUAT.bat" BuildCookRun "-project=$Project" -noP4 -platform=Win64 -clientconfig=Development -build -cook '-map=/Game/Coastal/Maps/L_SystemsTest_Integrated' -stage -pak -archive "-archivedirectory=$Package" -unattended -utf8output
& "$Package/Windows/CoastalExploration/Binaries/Win64/TP_ThirdPerson.exe" -RenderOffscreen -d3d11 -Windowed -ResX=1280 -ResY=720 -Unattended -NoSound -stdout -FullStdOutLogOutput -CoastalAcceptance=new -CoastalAcceptanceSlot=coastal_test_unique_name
& "$Package/Windows/CoastalExploration/Binaries/Win64/TP_ThirdPerson.exe" -RenderOffscreen -d3d11 -Windowed -ResX=1280 -ResY=720 -Unattended -NoSound -stdout -FullStdOutLogOutput -CoastalAcceptance=continue -CoastalAcceptanceSlot=coastal_test_unique_name
```

Choose a fresh test slot for New and use that same slot for Continue. Preserve its Saved/SaveGames and Saved/CoastalAcceptance evidence. Check explicit COASTAL_ACCEPTANCE_PASS/FAILED markers, campaign identity and process completion; the editor can report exit 0 even after a requested failure exit. The probe emits its pass before the final UI quit sequence, so also verify the exit_without_save step and clean process exit.

Additional development save modes are `partial_new` and `partial_continue`, using the same fresh `coastal_test_` name. The first leaves a battery in storage and records campaign/payload evidence; the second checks that evidence after actual Continue, then finishes the mission. `write_failure` requires a completed disposable campaign and its prior expected-ID file. It backs up both existing writable slots to acceptance evidence, temporarily makes only those two files read-only, invokes UI Save, checks disk/live-state conservation, restores attributes and retries. Preserve an external cleanup path for crashes and verify attributes after exit; never run against personal saves. Existing fault backups are not overwritten. Raw fixtures remain external to this repository.

For capacity acceptance, `tools/unreal/build_capacity_room.py` creates a separate `/Game/Coastal/Maps/L_SystemsTest_Capacity` from the integrated room in the full editor. It refuses an existing target or unsaved editor work, backs up the source map, explicitly loads the new copy before adding actors, and checks source preservation. Use forward slashes in `-ExecutePythonScript` paths: Unreal's Python launcher can interpret backslash escape sequences. The fixture has exactly the original seven objects plus 72 individually identified postcard pickups. Bootstrap selects its strict 79-object manifest and separate `level.systems_test.capacity` save-map ID; the normal map retains its original strict manifest.

Cook both maps with `-map=/Game/Coastal/Maps/L_SystemsTest_Integrated+/Game/Coastal/Maps/L_SystemsTest_Capacity`. Pass `/Game/Coastal/Maps/L_SystemsTest_Capacity` as the executable's first argument, then use `-CoastalAcceptance=capacity_new` and a fresh test slot. This collects 24 physical pickups through Hyper, verifies battery refusal and saves. Relaunch that map and slot with `-CoastalAcceptance=capacity_continue` to verify exact full-backpack restoration, repeat the refusal, transfer three postcards through the native UI, and complete the radio mission. Check `COASTAL_CAPACITY_PASS`, absence of `COASTAL_ACCEPTANCE_FAILED`, the final `exit_without_save` step and process completion. UI commands use Slate gamepad navigation; positioning and E input remain automated. For full-cabin acceptance, use `capacity_storage_new` and `capacity_storage_continue` with another fresh slot on the same capacity map. These fill the cabin through two batches of world pickups and UI transfers, verify refusal with zero and one free cell, restore the full save in a fresh process, then free two cells and complete the mission. Their success marker is `COASTAL_STORAGE_CAPACITY_PASS`; verify the same failure/quit/process conditions.

## Standalone Windows checks

Use Python with `PYTHONUTF8=1` (the retained verifier has some default-encoding reads). The source verifier scans all files; run on a clean source snapshot for stable counts because generated native intermediates add meaningless file-presence checks.

GCC runs with the installed MinGW compiler through Git Bash. Clang requires the VS 2022 developer environment for standard-library headers. For the PowerShell runner, enter that environment and invoke `tools/run_core_tests.ps1`; strict `/W4 /WX` remains enabled.

The sanitizer runner now permits an explicit ASAN_OPTIONS override. On Windows set `ASAN_OPTIONS=detect_leaks=0` and put LLVM's actual clang runtime DLL directory on PATH. This runs AddressSanitizer/UBSan; leak detection is **not_run**, since this platform rejects it. The default command retains leak detection on platforms that support it. Preserve initial failed runs separately.

All local machine paths, full compiler/runtime logs, private device identifiers, downloaded archives and external host assets remain in the workspace outside the repository. The public native evidence contains only reviewed summaries. Original `evidence/`, `VALIDATION_REPORT.md`, `AGENTS.md` and `SHA256SUMS.txt` are unchanged historical delivery records.
