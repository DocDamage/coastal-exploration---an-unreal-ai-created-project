## Remaining integration limits

The feature requires a single fixed character, a running registered consumer, normal walking mode, actual state sampling and one speed writer. Setting the opt-in flag alone is not input integration. If host code disables all execution while a speed is active, no unexecuted function can enforce freshness. External state changes that occur and revert wholly between observations cannot be detected without a revision/epoch signal. Same-valued foreign writes are not distinguishable from this owner's value.

The two-frame lease is frame-based, not a constant wall-clock duration. Jump/fall cancellation happens on observed mode changes and does not zero existing velocity. Unreal's MaxWalkSpeed also affects lateral falling speed; the actual host's braking/air-control behavior still needs playtesting. No stamina, auto-run or new traversal framework is included.

Preferences keep their existing namespace but explicit saves now use schema 2. The old M1.6 reader cannot read upgraded slots; back up both files before installing and do not downgrade against the upgraded pair. No write occurs on legacy load. An unverified write may still have reached disk; relaunch resolves the pair. CRC/read-back is not authentication, crash-atomicity or cross-process locking. Native raw reads can allocate the full file before bounded decoding. Campaign files are not removed to fix options.
